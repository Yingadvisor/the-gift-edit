# v0.5 acceptance test · no purchase required

Use the deployed site only after this release is uploaded and the Vercel deployment is Ready. This source ZIP alone does not update the public app.

1. Confirm the right column switches between **Ready-made gifts** and **Custom-made**, without clearing the same form. Before a first submission, Custom-made should show an empty prompt. Add an optional expression (e.g. courage), then select **Find gifts** to show product type + four original motif cards. Select a motif and see its inline status; no new form or external page is needed. Other must be the final relationship option, after Myself.
2. First try **Myself** under Your relationship: no recipient name is needed, labels say you, and `I love coffee` is valid. Switch back to Friend and confirm normal recipient fields/labels return. Then use a synthetic example: recipient `Demo Friend`, birthday, budget `100`, likes `They enjoy specialty coffee, gardening, and hosting dinner with friends.` Turn on AI-guided search only if you consent to sharing those non-identifying fields. There should be no product-query input. Select **Find gifts**; queries are generated from those interests.
3. Expect up to 10 distinct primary gifts, aiming for at least 5 if suitable current products exist. Check real USD prices and merchants. Greeting-card/wrapping products should not dominate unless explicitly requested. Fewer valid results must remain honest, not padded.
4. Refresh a listing, choose the exact variant and click **Add this variant to gift set**. Add a second different variant if the combined item prices fit $100. Adding must not create a checkout.
5. Check subtotal and remaining budget. Duplicate variants and additions over $100 must be blocked. Lower the budget below the subtotal: selected gifts remain, over-budget status appears and new checkout is disabled. Restore the budget.
6. Select a quick exclusion that conflicts with a chosen product, or change recipient preferences. The set must not remain checkout-ready; review/update the search and refresh again. Missing factor evidence must say **Can’t verify**, not promise safety.
7. With mixed merchants, see separate merchant groups and separate checkout buttons. No claim of one package, one shipping fee or a tax-inclusive total. For this acceptance test, do not click the checkout buttons. Actual checkout tests in the code use mocks only.
8. Enable **Must arrive by a date**, select a date, and search. Current Shop data lacks verified destination-specific arrival estimates, so unverified gifts must not qualify and the page must explain why. The date remains local. Turn it off and search again to see otherwise eligible gifts. This does not claim merchant dispatch/shipping policies were retrieved.
9. Put `They love Star Wars` in interests with intended audience Men and an optional adult age band. Listings must substantiate the theme; explicitly women-targeted products should not qualify, but a men’s necklace can. Unknown suitability must be disclosed. Returned cards should appear as optional add-ons; interests that explicitly request `birthday greeting cards` may show cards as main results. No unrelated padding to reach ten. Custom-made uses only the original four motifs, not new licensed franchise art.
10. Use **Show more options** when available. It must retrieve new live catalog data, preserve the set, omit duplicate variants and keep the same constraints. In AI mode, extra pages must be labeled rules-screened, not additional model picks.
11. Edit the expression without submitting: custom results keep the previous submitted brief. Submit to update, then switch modes without re-entering any details.
12. Report the visible safe error code/stage if an AI run fails. Do not share keys, checkout access URLs, delivery addresses or payment information in screenshots.

Shipping and tax are extra. Only the buyer reviews final merchant terms and decides whether to pay. No payment or order is required for this test.
